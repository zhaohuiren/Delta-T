# Delta T 通勤分段计时器

> 当前版本：0.6.2-test
> 更新日期：2026-10-03
> 目标设备：OPPO Find X8 Ultra，Android 16  
> 当前阶段：统一修复与回归验收

## 一句话定义

一款面向驾车通勤的 Android 单程分段计时器。用户打开 App 并进入准备状态后，车辆依次经过固定的 A、S1、S2、B 四个计时点，App 自动开始、分段和结束；A～B 之间允许选择任意道路，每次实际轨迹和成绩都保留。

## 不可偏离的产品约束

1. 不是环形赛道，不使用“圈”作为核心概念；路线是 A→B 的开放单程。
2. 上班（家→公司）和下班（公司→家）是两个独立方向、两套计时点和纪录。
3. A、B 是总程必须命中的固定起终点；S1、S2 是垂直于 A→B 总方向的全局进度线。
4. A～B 之间允许任意绕行。漏过 S1/S2 时继续计时，总程仍有效，只有缺少相邻端点的分段显示为 `--`。
5. 首次基准行程驾驶过程中不要求点击。到达并停车后，才在已记录轨迹上标记四个计时点。
6. 日常使用不要求后台自动唤醒。用户主动打开 App，点击一次“一键准备”，应用按最近的 A 点自动识别方向。
7. 进入准备后允许锁屏；计时、定位和轨迹记录必须继续，并提供常驻通知。
8. 日常计时页使用黑底遥测风格，独立显示月/周 Delta、分段颜色和过滤后的最高速度；在线且同意隐私提示时使用高德地图；离线、未同意或地图失败时使用本地简洁轨迹图。

基于 0.6.1 统一修复：终点最近接近候选、低精度点隔离、漏点实时 Delta 与历史重算、源轨迹 Mock 拒绝、插值选点时间和升级幂等、录制结束标点入口、编辑校验方向，以及完成页成绩一致性。

- 周统计、排行榜本周、周纪录和计时参考统一为周一开始的自然周，跨月不截断；比较规则版本为 4。
- 数据库 v5 → v6 增加计时点版本的引擎元数据和源选点插值时间。保留原轨迹与旧评估；无法可靠恢复源时间时保留旧活动版本，支持明确重试。
- 新引擎版本为 4，兼容旧版记录。
- 本轮计划与验收证据保存在本地主项目目录的开发计划和 `dist/` 中。

## 0.5.0 功能

- 计时引擎升级为 v2：S1/S2 使用无限延伸的平行进度线，并通过连续 3 个线后合格点或深入 25 米确认。
- 支持稀疏通过记录：等待 S1 时命中 S2 会把 S1 标记为缺失并继续；到 B 时补记剩余中间点缺失并完成。
- A/B 完整即可形成有效总程；只有相邻检查点都命中时才生成对应分段。旧 v1 总程仍可比较，理论最佳和分段纪录只使用 v2。
- 纪录页新增排行榜、月统计、周统计；排行榜默认本月，并支持本周、全部和包含起止日的自定义日期范围。
- PB、P1 GAP、有效行程数和理论最佳随当前路线与筛选范围统一重算；月/周趋势使用有效总程算术平均值。
- 主界面与通知以 `卫星 已用/可见` 展示所有星座汇总，星座细分继续保存在诊断记录。
- 移除在线地图 SDK、地图设置、隐私门和地图构建变体，恢复单一 `debug/release` 构建。

## 0.4.0 功能

- 完成成绩改为严格比较：质量 A/B 只要更快即刷新纪录；动态容差仅用于实时估算防闪烁。
- 月、周比较完全独立；没有本周参考但有本月参考时，颜色与慢/快判定自动回退到本月参考。
- S1/S2/S3 分别使用各自的月最快、周最快行程作为参考，完成结果与实时显示一致。
- 启动时一次性按规则 v3 回填历史 Session、分段与计时点版本评估，不破坏既有表结构。
- 首页将上班/下班并入一个紧凑路线卡，各自计算本周最快和最近成绩；路线行直接进入编辑，路线库移至设置。
- 历史页保留全部记录并动态显示本月/本周双标签；删除操作降为次级菜单。
- 个人纪录取消日历，改为当前方向全部历史有效 A/B 成绩的 F1 排行榜，含 P1/PB、GAP、三分段和理论最佳。
- 移除面向用户的“固定基准”；路线源轨迹只作为路线与计时点的内部依赖并受删除保护。

## 0.2.2 功能

- 计时页改为自适应单 Δ：紫色只显示月 Δ，绿/黄色只显示周 Δ，颜色、数字和结论使用同一基准。
- S1/S2/S3 分段卡同样只显示判定 Δ，历史详情仍保留月/周完整对比。
- 压缩计时板与分段区高度，为实时轨迹留出更多空间。

## 0.3.0 功能

## 0.2.1 功能

9. GPS、北斗及手机支持的其他 GNSS 星座由系统联合定位；App 不强制单一星座。

## 已冻结的颜色语义

- 紫色：本月最快 / 严格快于月参考。
- 绿色：本周最快 / 严格快于周参考；也用于 GNSS 良好状态。
- 黄色：慢于当前有效参考；周参考不存在时回退月参考。
- 白/灰：持平、没有可比较参考、未开始、无效或低可信。
- 月、周标签可同时出现，颜色必须配合文字，不作为唯一信息载体。

## 推荐实现顺序

先实现纯 Kotlin 的几何与计时核心，再做模拟轨迹回放；算法通过后接 Room、前台定位服务和 Compose 页面。抽象路线显示不参与计时判断。

## 第一版成功标准

- 用户可安全录入一条上班和一条下班基准。
- 日常打开 App 后可在锁屏条件下完成 A→B 计时。
- 改走其他道路仍正常记录；漏过 S1/S2 不会卡住总程，缺失分段不参与分段纪录。
- App 被锁屏、切到其他应用后，前台定位服务不中断。
- 全部历史可查看，基准、个人最佳、分段最佳彼此不混淆。
- 测试手机 OPPO Find X8 Ultra / Android 16 连续 10 次实测无崩溃、无丢行程。

## Android 工程

当前目录已经包含可构建的 Delta T Android MVP：

- 应用名：Delta T
- applicationId：`app.deltat.commute`
- 构建类型：单一 `debug/release`，不包含第三方地图 SDK 或 API Key
- 交付构建：`debug`（当前版本 0.5.0-test）

具备 JDK 17 与 Android SDK 36 时，运行 `scripts/build-apk.sh` 可执行单测、Lint 和 APK 构建。产物复制到 `dist/Delta-T-0.6.0-debug.apk`。

交付 APK 默认不包含覆盖率插桩。

### APK交付约定

后续可安装且已验证的APK统一放到用户指定的 `smb://DXP4800-861B._smb._tcp.local/ssd/app/`（NAS实际目录`/volume2/ssd/app/`），本地`dist/`保留副本。构建脚本仅生成本地产物，交付时还须执行NAS上传与SHA-256校验，不将“构建成功”当作“已上传”。

命名：`Delta-T_v<版本>_<构建时间YYYYMMDD-HHmm>_<简短变更说明>_<SHA256前8位>.apk`。使用北京时间，保留测试版标识和历史包；不上传中间包或androidTest APK。具体执行规则见`AGENTS.md`的“APK交付位置与命名”。
